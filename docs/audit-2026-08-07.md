# Audit — 2026-08-07

A full audit of the model and every recorded metric, triggered by a loss of
confidence in the numbers after the stage 2(a) resolution run. Read this before
interpreting any result from before this date.

## The verdict in one line

**The numbers were arithmetically correct. The comparisons were not.**

Every recorded figure regenerated exactly from the artefacts. What was broken
was what those figures were being compared *against*, and the fact that neither
run 1 nor run 2 was a fair test of the branch architecture.

## What survived the audit

- **Every run-1 number reproduces from disk.** Headline per-mission gaps, both
  quartile ladders and their trend slopes, all ten absolute transit bands with
  their row counts, all five span-by-count cells, the K2 benchmark, the noise
  floor. Regenerate with `pipeline/scripts/evaluate.py compare`.
- **The metric implementations are exact.** `SliceMetrics` checked against
  sklearn and against a brute-force sweep of every achievable threshold: zero
  difference on ROC-AUC, PR-AUC, Brier, ECE and recall at 1/5/10% FPR. Pinned by
  `test_slice_metrics_agree_with_reference_implementations`.
- **The leakage guarantee holds structurally.** Both trainers use
  `StratifiedGroupKFold` grouped on `tic_id`.
- **The resolution falsification stands, and is stronger than reported.** Run 2
  lost *every fold* against run 1 (deltas −0.042, −0.049, −0.018, −0.037,
  −0.010; mean −0.0313, d = −1.92). Both runs carried the same defects, so the
  branch-versus-branch comparison is unaffected by everything below.

Two corrections to the record: a Kepler Q2 quartile gap misprinted as +0.0336
(actual +0.0335), and a false claim that "every low-count TESS cell sits at or
below zero" — the narrow-span low-count cell is **+0.0243 on n=417**, the
largest of the three. Neither changes a decision.

## Why neither run was a fair test of the architecture

Four defects, all fixed, all present in run 1 and run 2:

1. **Missingness was a near-perfect mission indicator.** `NaN → 0.0` at shard
   write, then normalised against constants fitted on present-only rows, put
   "unmeasured" at a real percentile of its own column — a missing
   `odd_even_statistic` at z = −0.679 against a real 5th percentile of −0.68.
   Every Kepler and K2 row is missing; only 12.8% of TESS is.
2. **Two fusion inputs were constants on 56% of rows.** The `detection` and
   `ghost` towers are fed entirely from the DV report and were ungated, so they
   emitted `relu(bias)` for 100% of Kepler and K2 — exactly the "learned bias on
   zeros" the design exists to prevent.
3. **`bootstrap_significance` was a dead input.** Median 3.8e-146, MAD 1.1e-138
   → the degenerate-scale guard substituted 1.0 → the ±10 clip collapsed 1,378
   distinct values to effectively `{−1, 0}`.
4. **Every batch held one mission.** The catalogue is mission-blocked and the
   shuffle buffer was 1,024 over a ~3,470-row split, so `BatchNormalization`
   statistics were computed per-mission and each epoch walked the missions in
   order as an unintended curriculum.

**None of this is resolution.** It is a better explanation for both runs than the
hypothesis that was falsified.

## The recurring defect class

Five instances before this audit, eight found during it: **a check that returns a
plausible answer instead of failing.** Every fix below converts one into a loud
failure.

| finding | was | now |
|---|---|---|
| Missing DV scalars | filled with 0.0 at write | NaN through to the reader, imputed to the fitted centre (z=0) |
| Scalar-only branches | ungated | gated on `dv_usable` |
| `bootstrap_significance` | linear, scale forced to 1.0 | log10 **at write time**, before the float32 cast |
| DV `-1.0` sentinel | unscrubbed on 2 fields | scrubbed; non-positive on a log column is unmeasured |
| A dropped feature column | `log.warning` | `raise` |
| `secondary_phase` | written, normalised, read by nothing | scoped to `secondary_view`; invariant test ties the literals |
| Prediction alignment | asserted on binary labels | asserted on `tic_id` |
| `promote()` | accepted a run with no checkpoints | `assert_servable` refuses it |
| `quarantine_tics` | called by nothing outside its test | persisted by the gate, applied in `run_cv` |
| Zero-shot contamination filter | skipped silently if the file was absent | raises unless explicitly overridden |
| Uninitialised scores | `np.empty` returned as probabilities | `np.nan` + hard raise |
| Unmatched-population gate | compared pooled means | refuses, naming the fix |

### The float32 trap, found by checking the fix

The log transform was first applied at *read* time. That looked right and was
not: **1,639 of `bootstrap_significance`'s 2,235 measured values are below
float32's smallest normal (1.18e-38) and underflow to exactly 0.0 in the
TFRecord**, while `fit_scalar_constants` reads the float64 index. The constants
were fitted on values the model would never see. A read-time transform cannot
recover information the storage format already destroyed. It now happens at
write time, and the shard metadata records `log_scaled_columns`.

Verified after the reshard: distinct z-values 2 → **1,331**.

## Performance

- **`_unfolded`: 122.79 ms → 2.58 ms (48× measured)**, byte-identical output.
  One pass over the cadences instead of one per epoch.
- **Shard decodes per CV run: 20 → 1.** `parse_viewset_shards` caches the decoded
  stream once; only per-fold normalisation reruns. Also four live caches per
  fold → one for the whole run.
- Corrected a docstring claiming ~100 MB for the cached set; it is 670 MB since
  the 2001-bin restore, which was the basis for calling the cache affordable.

## Adopted from ExoMiner

- **Shared conv tower over the flux family.** `local_view`, `odd_view`,
  `even_view` and `secondary_view` are the same measurement at 201 bins and now
  pass through one `TimeDistributed` tower; fusion takes **`odd − even`**, gated
  on both halves. Four independent towers meant an odd-versus-even difference
  was partly a difference between two sets of kernels. **233,617 → 215,281
  parameters**, which also puts the model *below* the incumbent's 227,641 and
  removes the capacity confound that muddied run 2.
- **Paired-fold comparison** (`validation.promotion.paired_folds`). Pairing on
  fold index removes fold difficulty, the larger variance source. Reported and
  alarmed, never blocking: at five folds the two-sided Wilcoxon floors at
  p=0.0625 and can never reach 0.05, so `MIN_PAIRS_FOR_P_VALUE` suppresses the
  p-value below six pairs rather than inviting "not significant" to be read as
  "no effect".
- **N models per fold** (`CVConfig.n_models_per_fold`), averaged before
  calibration, with each member's own AUC recorded. `summary.variance` reports
  `seed_sd` and `fold_sd` **separately** — the decomposition the ±0.0106 has
  always conflated. `seed_sd` is `None` at one model per fold, because one draw
  cannot measure it.

### On ExoMiner itself

Their vetting app is a 270-line static table browser with **no plots**; v2's
console does strictly more per candidate. They have **no calibration at all**
(their own tooltip says the score "is NOT a probability"), **no promotion
concept**, `tf.random.set_seed` appears **zero** times, 258 hardcoded personal
absolute paths, and one genuinely runnable test file. Their ~30 C/C++ files are
inherited Google AstroNet code, duplicated byte-identically in two directories
and wired to nothing.

What they have that v2 does not is **distribution**: a published survey-scale
catalogue with per-row uncertainty, a DOI and a citation ask. That is a
publishing gap, not an engineering gap.

### Found and closed on 2026-08-08, from the code audit

- **Calibration never checked convergence or class balance.** `fit_platt` and
  `fit_temperature` returned `res.x` without reading `res.success`, and neither
  guarded a single-class validation split — where the NLL is minimised at the
  extremes, so the optimiser converges and returns a scaler mapping every score
  to one end. That bundle is written to disk as the *servable* calibrator. Both
  now raise.
- **`_gate_slice` fell through to pooled means** when `per_mission` existed but
  lacked TESS, while reporting that the summary "predates the per_mission
  block". `_population_mismatch` compares mission *sets*, so two summaries both
  missing TESS agreed with each other and never triggered the refusal. Now
  raises.
- **A null mission became the string `"nan"`** — `pd.Series.get` returns the
  stored NaN rather than the default, so it keyed its own view cache and
  resolved to a TESS light-curve path. Validated once at catalogue load.
- **`--assemble-only` over a partial cache reported a clean build.** Misses are
  counted and reconciled against the recorded skip reasons; an unexplained
  shortfall raises unless `--allow-partial`.
- **Five merges in `eval/comparison.py` had no `validate=`**, so a repeated
  `tic_id` on either side would silently multiply rows and every comparison
  table would be computed over a population that does not exist.
- **The gate compared TESS slices of different sizes** (2,367 vs 2,399) with
  nothing checking it. Now alarmed.

### The unfolded branch does not do what it says — decide before stage D

**Verified live 2026-08-08, and it is stage 2(b)'s whole mechanism.**
`_branch` (`models/cnn_branches.py:144-151`) documents "convolve each transit
with shared weights, then pool across transits, so the branch sees
transit-to-transit variation rather than an average". The code does:

```python
x = layers.Reshape((transits, view.shape[2] * view.shape[3]))(view)   # (20, 603)
x = _conv_tower(x, ...)                                               # conv along TRANSITS
```

So the convolution slides along the **transit** axis while the 201 phase bins ×
3 channels are flattened into 603 **unordered** channels. The within-transit
phase structure — the transit shape itself — is destroyed before the first
convolution, and there is no weight sharing across phase. The branch cannot see
what a single transit looks like; it can only see how flattened transit vectors
vary down the sequence.

This is also the one place the roadmap's "adopt from ExoMiner" is not adopted:
their `build_conv_unfolded_flux` wraps the tower in `TimeDistributed` over the
phase axis, which is exactly what the comment describes.

**Not fixed here, because it is a design decision rather than a defect fix.**
The mechanical part is clear — a `_conv_tower_model` over `(bins, channels)`
under `TimeDistributed`, then a pool across transits. The part that needs a
call is *which* pool: plain average pooling returns the mean transit, which is
the thing the comment says the branch exists to avoid, so it likely wants
average **and** max (or a spread statistic) concatenated. That changes the
parameter count and the branch's meaning, and stage 2(b)'s success criterion
rests on it.

**Sequence it into stage D**, before any run is used to judge whether the
unfolded branch earns its place — measuring the current implementation would
answer a question about a branch nobody intended to build.

### Newly found, still open

- **The inner validation split is unstratified**, in two places, and there is a
  third `GroupShuffleSplit` that is *not* this bug — name the file or the wrong
  one gets fixed:

  | site | what it splits | affected |
  |---|---|---|
  | `training/train_branches.py:376` | inner train/val, feeds the Platt fit | **yes — produces every stage-2 number** |
  | `training/train.py:222` | inner train/val in the incumbent trainer's CV path | yes, same defect |
  | `training/train.py:132` | group-aware train/test *holdout* | **no** — a test split, nothing calibrates on it |

  `GroupShuffleSplit` does not guarantee both classes reach the Platt fit, which
  calibration requires. Safe in production (~868 validation rows) and it is why
  the tiny test fixtures need `val_frac=0.5`. `StratifiedGroupKFold` is the fix;
  `train_branches.py:376` is the minimum, since it is the one behind every
  stage-2 decision. Applying it **changes the inner partition and therefore the
  numbers**, so it belongs between experiments, not between a run and its own
  control.
- **`eval/scoring.py`'s `score_run` is still untested.** `summarise_scored` now
  has coverage; the model-loading path does not.
