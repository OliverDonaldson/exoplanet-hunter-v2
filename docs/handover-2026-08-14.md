## 2. What stage 8 found, final

Full detail in `roadmap.md` under **Stage 8 result**. The headline is unchanged:

**Propensity weighting eliminated the branch architecture's amplification of the
observation-baseline confound, at no measurable cost.** On the frozen 2,399-row
out-of-fold TESS slice the amplification gap went **+0.1265 → −0.0071**, **3.3×
its own measured bar**, with TESS AUC and shortlist recall both inside their
noise floors. Synthetic negatives were **null** (0.1×). Arm S is **not
comparable** — it never scored 680 of the pre-registered rows.

**All four pre-registered predictions were falsified.** Prediction 4 was measured
2026-08-14 and is the new material:

- The control-arm split fell **+0.1690 → +0.0724**, a paired **−0.0966**, **1.3×**
  its pre-registered bar, bootstrap CI [−0.157, −0.039].
- **But threshold-free host-scoring did not move**: host-AUC on transit-free
  light curves is 0.6234 → 0.6045, paired CI [−0.060, +0.019], p≈0.33.
- So the pre-registered statistic moved and the construct it stands for did not.
  Recorded as a **qualified** second win. **Do not bank it** without a
  threshold-free confirmation.
- Stage 8's control split at **+0.1690** against stage 7i's **+0.1195** on the
  same hosts with the same code — **+0.0494 from reseeding alone**. Running the
  control was what kept that drift from being credited to the intervention.

**The measurement everything above rests on is thin in one place.** The split's
reseeding noise is characterised by exactly one control retrain, and that single
draw is half the size of the effect claimed from it.

## 4. Open decisions for Ollie — ask, do not assume

1. **Which branch model enters the ensemble.** Stage 10.5 was sequenced after
   stage 8 because *"stage 8 changes the labels both models learn from"*. It did
   not: group (a) was skipped, so the labels never moved. What stage 8 did change
   is the **training weighting**, and arm P showed that change is worth keeping.
   So the ensemble's branch member could be the plain control or the
   propensity-weighted model, and the pre-registration does not say which.
   **Recommend the propensity-weighted arm** — it is the one carrying the stage's
   only deliverable, and an ensemble built on the un-weighted control would
   re-import the amplification stage 8 just removed. Ollie's call, and it should
   be recorded before the run, not after.
2. **Whether the qualified second win gets a confirmation run.** A threshold-free
   re-measurement of host-scoring would settle whether propensity weighting
   actually reduces it. Cheapest as an addition to stage 10.5's control-arm pass
   rather than as its own stage.

   they carry — the control's pooled gate-recall floor came in at 0.0720 against
   stage 6's 0.0337. Widening `--n-models-per-fold` costs compute linearly.

## 5. Operational facts

**Two corrections to `handover-stage-8-close.md`, both found by checking it
against the artefacts:**

1. **"The four stage-8 arms span two SHAs" is wrong.** All four record
   `git_sha 51e256ba733ca52a6fb767018f58709c1c24a959`. The reassurance it was
   reaching for is therefore stronger than it claimed: there is no code delta
   between the arms at all.
2. **"Regenerate the stage-3 incumbent summary — the label change invalidates
   it" was wrong on both counts.** The 2026-08-08 refresh flipped zero labels,
   and `summarise` could not have propagated a label change anyway — it takes
   `y_true` from the predictions parquet and re-joins only `mission`. The summary
   regenerates byte-identical. Details in `roadmap.md`.

**Carried forward, all still true:**

- **Nothing long-running goes in `/private/tmp`.** It has cost this project
  twice. Use `~/Downloads/.stage8-scratch/`.
- **`setsid` does not exist on macOS.** `screen -dmS <name> caffeinate -dimsu
  <script>` reparents to PID 1 and survives the session. Used for prediction 4;
  it works.
- **Do not hold a long Bash waiter against a detached job.** Poll for the
  artefact, or arm a monitor on a progress file. Prediction 4 used a progress
  file with per-arm exit codes plus a watchdog for the screen session
  disappearing — that covers the crash case, which a success-only grep does not.
- **`caffeinate`'s `PreventSystemSleep` only works on AC power.** Verified again:
  on battery `pmset -g assertions` showed `PreventSystemSleep 0` with only the
  idle assertion held. **Check it reads 1 after launching, not before.**
- **A CV run is ~2 h** at 5 folds × 3 models.
- **The stage 7i harness is ~50 min per arm** and hit its estimate: 48 min for
  the control, 49 for propensity, 1 h 37 for both.
- **Run the test suite one process per file**; `test_train_branches.py` alone is
  ~6 min.
- **Never edit `pipeline/src/**` or `pipeline/scripts/train_branches.py` while a
  multi-arm block runs** — the runner launches a fresh interpreter per arm.
  `api/`, `frontend/`, `docs/` and `pipeline/tests/` are safe.
- **Every commit changes the `git_sha` recorded by runs launched after it.**
  Batch doc commits until a block finishes.

**New, and worth keeping:**

- **Simulate the draw in pandas before spending the compute.** Prediction 4's
  host selection — fold routing, the intersection with the incumbent, the depth
  and cache filters, the seed-42 matcher — is all pandas and runs in seconds. It
  was reproduced to a `tic_id` checksum *before* launching the 1 h 37 block, so
  "is this the pre-registered draw?" was answered for free instead of after two
  hours of building view sets.
- **The control-arm split is threshold-sensitive.** Any future reading of it
  should carry a threshold-free companion. See §3.
